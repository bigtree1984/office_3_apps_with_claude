# ノウハウ：Figma の文字を PowerPoint で同じ位置に出す（2026-09-20）

Figma で作った通りに配置しても、PowerPoint では**文字が少し下にずれて見える**。原因は3つで、対処も3つ。

## 1. 行間は「％」ではなく「ポイント」で指定する

| | 基準 | 例（本文 14pt・行間 140%） |
|---|---|---|
| Figma | **文字サイズ**に対する倍率 | 19.6pt |
| PowerPoint の「％」 | **フォント自身の行送り**（およそ 1.2 倍）に対する倍率 | 140% ≒ 23.5pt（広すぎる） |

→ XML では `<a:lnSpc><a:spcPts val="1960"/></a:lnSpc>`（1/100 pt 単位）。
`spcPct` を使うと、同じ数字を書いても Figma より広くなる。

## 2. 行の高さの「余り」の置き方が違う

- Figma：余りを行の**上下に半分ずつ**配る。
- PowerPoint：余りを行の**上側**に積む。→ 文字が下がって見える。

→ **テキストボックスの縦位置を「中央」にする**（`<a:bodyPr anchor="ctr">`）。箱の高さを Figma と同じにしてあれば、
余りが均等に配られて Figma と一致する。

### ただし例外：文字量が変わる枠は「上揃え」

本文プレースホルダーのように行数が増減する枠を中央にすると、行数が少ないときに文字が枠の真ん中に浮く。
→ **本文枠（obj プレースホルダー）とマスターの本文は `anchor="t"`**。タイトル・リード文・ラベル・キャプションなど、
箱の高さ＝文字の高さのものだけ `anchor="ctr"`。

## 3. 内側の余白（インセット）は 0 にする

PowerPoint のテキストボックスは既定で左右 0.25cm・上下 0.13cm の内側余白を持つ。Figma には無い。
→ `lIns="0" tIns="0" rIns="0" bIns="0"`。

## 4. 折り返しは切る（2026-09-20 方針）

固定サイズのラベル（タイトル・リード文・Organism の文字）は **`wrap="none"`**。
収まらないときは、変な位置で折り返すより**右にはみ出したほうが気づける**（芝野さん判断）。
本文枠だけは `wrap="square"`（箇条書きが枠外に出ると読めないため）。

## まとめ（XML の型）

```xml
<a:bodyPr wrap="none" lIns="0" tIns="0" rIns="0" bIns="0" anchor="ctr"><a:noAutofit/></a:bodyPr>
<a:lstStyle><a:lvl1pPr algn="l">
  <a:lnSpc><a:spcPts val="1960"/></a:lnSpc>      <!-- 14pt x 140% -->
  <a:spcBef><a:spcPts val="0"/></a:spcBef><a:buNone/>
  <a:defRPr sz="1400" b="0"> … </a:defRPr>
</a:lvl1pPr></a:lstStyle>
```

## 5. 図形のラベルは「中心を計算して」置く

丸の中の番号、シェブロンの中の文字、点と対になるラベル——**見た目で置くと数 px ずれる**。
PowerPoint 側でテキストボックスを縦中央にしてあるので、Figma 側で中心をそろえておけば一致する。

```
ラベルの y = 図形の y + 図形の高さ/2 − ラベルの高さ/2
```

実際、13個の Organism のうち5個・24か所でずれていた（1〜4px）。小さいが、拡大すると気づく。
**Figma を直してから、書き出し済みの JSON にも同じ計算を適用する**（順序を逆にすると SSOT がずれる）。

## 6. 折り返しをオフにした以上、文字数の上限は「測って」決める

折り返しをオフ（`wrap="none"`）にすると、長い文章は**静かに枠の外へ出る**。
PowerPoint は警告してくれないので、実際の運用レポートで1行だけ画面外へはみ出していた。

上限は感覚ではなく、**フォントの字送り（advance width）から計算できる**。

```python
from fontTools.ttLib import TTFont
f = TTFont("NotoSansJP-Bold.ttf")
upm = f["head"].unitsPerEm
w = sum(f["hmtx"][f.getBestCmap()[ord(c)]][0] for c in text) / upm * pt   # 表示幅（pt）
```

Noto Sans JP では、全角＝1.000em、半角英数＝0.568em（Bold 0.600em）、半角スペース＝0.224em。
これで `scripts/fit_text.py` を作り、`placeholder()` から呼んで**生成時に警告**するようにした。
上限の表は `bigtree/design/CONTENT_RULES.md` §8。

学び：**書式の既定を変えたら、その副作用を検出する仕組みもセットで作る。**
折り返しオフは見た目のための判断だが、そのぶん「はみ出しに気づけない」という穴が開く。

## 7. 図形の座標を目分量で書かない（注記の位置）

グラフの下に注記を足したとき、y を目分量（392px）で書いたらグラフに重なった。
**ゾーンの高さから引き算して決める**と重ならない。

```python
NOTE_H, NOTE_GAP = 31, 12          # 補足1行の高さ／すき間
note_y  = zone_h - NOTE_H          # 注記は最下段
chart_h = zone_h - NOTE_H - NOTE_GAP   # 中身はそのぶん低くする
```

後から足した要素ほど検証を飛ばしやすい。**足したら必ず PDF にして見る。**

## 8. Figma で折り返している文字は、Office では折り返らない

Figma のテキストは幅を決めると自動で折り返し、**高さが2行ぶんになる**。
その座標をそのまま PowerPoint に持っていっても、`wrap="none"` なら**1行のまま横へ溢れる**。
見た目が違うのに、書き出した JSON の数字は同じなので気づきにくい。

見分け方：**枠の高さ ÷ 1行の高さ** が 2 以上なら、Figma 側で折り返している。

```python
lines = round(h_px / (pt * line_pct / 100 * 2))   # 2px = 1pt
```

対処は**置き場所で変える**。

| | 折り返し | 理由 |
|---|---|---|
| レイアウトのプレースホルダ | **オフ** | 溢れたら気づける。枠は目安で、中身は後から人が入れる |
| 図解（Organism）の中の文字 | **オン** | 枠の大きさが図の一部として決まっている。溢れると図が壊れる |

実際、20個の図解のうち2個・5か所で溢れていた（2026-09-21、簡易プレビューを作って初めて発覚）。
`fit_text.fits_box()` は折り返しを考慮して「何行必要か」を返すので、図解の判定にはこちらを使う。

## 9. 行間を固定値にすると、文字グリッドの影響そのものが消える

日本語 Word は既定で**行を文字グリッドに吸着**させる。同じ原稿でも、グリッドありは行が間延びしてページ数が増える
（この一式のサンプルで 3 ページ → 4 ページ）。

対処は2つあり、**どちらか一方で足りる**。

1. グリッドを無効にする（`<w:docGrid w:linePitch="360"/>` ＋ 各スタイルに `<w:snapToGrid w:val="0"/>`）
2. **行間を固定値にする**（`w:lineRule="exact"`）。固定値の行はグリッドに吸着しない

この一式は2を採用しているため、**あとからグリッドを有効にしても見た目が変わらない**。
つまり「グリッドあり／なし」の比較を見せたいときは、**行間を Word 既定（自動）に戻す必要がある**。
`build_dotx.py` の `AUTO_LINE` がそれで、比較用の2ファイルを書き出す。

学び：**対処を重ねると、もとの問題を再現できなくなる。** 説明用の比較が要るなら、
「直す前の状態」を再現できる形で残しておく。
